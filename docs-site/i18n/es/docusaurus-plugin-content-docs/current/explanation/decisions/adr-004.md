# ADR-004: Validación escrita a mano, que falla de forma cerrada, tras Standard Schema

## Estado

Aceptada. Vigente en 0.5.x.

## Contexto

`@brambodev/contracts` debe seguir sin dependencias para que un autor de puertos pueda instalarlo solo, pero los hosts ya usan bibliotecas de esquemas como Zod o Valibot. La validación está en fronteras de confianza, donde un valor por defecto permisivo es una vulnerabilidad.

## Decisión

- Los esquemas propios de brambo son validadores escritos a mano, expuestos mediante una reproducción estructural de la interfaz Standard Schema v1 (`~standard`), de modo que las bibliotecas que implementan Standard Schema interoperan sin dependencia.
- La validación falla de forma cerrada: todo lo desconocido, no demostrado o mal formado se rechaza con un `BramboError` con código y nunca se completa con un valor por defecto.

## Consecuencias

- Ningún paquete depende de una biblioteca de esquemas.
- Los validadores indican las coordenadas dentro del mensaje en lugar de en `path`.
- Los llamadores deciden según `error.code`, nunca según el texto del mensaje.
- Los autores de puertos pueden escribir el esquema de configuración de un proveedor con cualquier biblioteca de Standard Schema, siempre que valide de forma síncrona donde el contrato lo exige.

## Evidencia

- `packages/contracts/src/standard-schema.ts` y `packages/contracts/src/validation.ts`.
- Ninguna entrada `zod` ni `valibot` en ningún `packages/*/package.json`.
- Ejemplos de fallo cerrado: `kernel/src/intercept.ts` (validación de límites), `projection/src/engine.ts` (modo), `contracts/src/sandbox.ts` (`validateSandboxCapabilities`).
