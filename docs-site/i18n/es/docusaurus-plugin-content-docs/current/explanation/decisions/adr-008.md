# ADR-008: Almacén de ejecuciones SQLite de autoridad única con CAS, leases y fencing

## Estado

Aceptada. Vigente en 0.5.x.

## Contexto

Los flujos durables necesitan revisiones atómicas y un relevo seguro tras una caída, pero brambo no debe afirmar una autoridad distribuida que no puede demostrar. El almacén es un puerto (`RunStore`), así que la implementación de referencia fija el listón que deben alcanzar las demás.

## Decisión

- El almacén de referencia es `workflow-store-sqlite` sobre `node:sqlite`, cargado de forma diferida para que importar el paquete no tenga efectos secundarios.
- Las confirmaciones son comparación e intercambio sobre una revisión; el estado, los eventos y la actualización del recibo se confirman en una sola transacción.
- Los leases son reclamaciones de todo o nada con épocas de fencing monótonas; una confirmación debe presentar épocas, dueño, hash del token y caducidad vigentes. Los tokens nunca se guardan en claro.
- Las escrituras usan `BEGIN IMMEDIATE`; la contención más allá de una espera acotada lanza `BRAMBO_WORKFLOW_STORE_BUSY` en lugar de sobrescribir.
- El alcance es un único host autoritativo; la misma suite de contrato publicada se ejecuta contra SQLite y contra un backend de proceso local.

## Consecuencias

- El almacén SQLite requiere Node.js >=24.15.0, mientras que el resto de paquetes admite Node.js >=20.
- No se afirma soporte para montajes compartidos, clústeres ni conmutación por error; otras topologías implementan `RunStore` y superan `runWorkflowStoreContractSuite`.
- Las importaciones entre almacenes son copias con fencing, no transacciones distribuidas.

## Evidencia

- `packages/workflow-store-sqlite/src/store.ts`, `coordination.ts`, `sqlite.ts` y `schema.ts`.
- `packages/workflow-store-sqlite/package.json` (`engines.node: >=24.15.0`).
- `packages/contracts/src/contract-suite/workflow-clauses.ts` (`runWorkflowStoreContractSuite`).
