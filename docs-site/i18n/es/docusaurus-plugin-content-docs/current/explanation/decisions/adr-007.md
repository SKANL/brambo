# ADR-007: brambo no es un sandbox; la autoridad pertenece al host

## Estado

Aceptada. Vigente en 0.5.x.

## Contexto

La ejecución de herramientas, los métodos y los executors cruzan fronteras de confianza. Que exista un tipo o una interfaz de adaptador no debe leerse como una garantía, y brambo se ejecuta en hosts cuyo aislamiento no puede observar.

## Decisión

- brambo valida y registra; el host autoriza. La autenticación, las credenciales, la aprobación, el despliegue, la retención y TLS son responsabilidad del host.
- `ToolProvider` solo descubre. La ejecución requiere `executeTool`, un `ToolExecutor` y una sesión de sandbox propiedad del llamador, con argv exactos y sin shell ni manejadores JavaScript.
- Los proveedores de sandbox informan evidencia de capacidades; una política que exige controles no demostrados se rechaza antes de que exista una sesión. Solo se afirma aislamiento del sistema operativo donde un proveedor lo demostró.

## Consecuencias

- El adaptador CLI se documenta como ejecutor de procesos de proveedores con los privilegios del usuario.
- bubblewrap en Linux solo se anuncia tras una prueba funcional; macOS solo afirma evidencia del sistema de archivos; Windows requiere un broker externo; el proveedor remoto es un transporte inyectado.
- El coordinador de flujos no incluye TLS ni autenticación propia; llama a funciones del host.
