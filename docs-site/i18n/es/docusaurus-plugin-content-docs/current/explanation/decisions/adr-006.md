# ADR-006: CLI de proveedores como registros de rasgos; executors de API mediante un registro explícito

## Estado

Aceptada. Vigente en 0.5.x.

## Contexto

brambo controla tanto CLI de programación (Claude Code, Codex, OpenCode) como API de modelos alojadas (OpenAI, Anthropic). Los proveedores no son intercambiables, y cargar código nombrado por la configuración permitiría que un archivo de configuración eligiera qué se ejecuta.

## Decisión

- `adapter-cli` es un único motor genérico. Cada executor de CLI es un registro de datos (comando, argumentos fijos, entrega del prompt, análisis de la salida), no una clase: `claude-code`, `codex` y `opencode`.
- Los executors de API viven en `adapter-api` (registro, reintentos y bucle de herramientas) más los paquetes de cada proveedor. Un identificador de proveedor selecciona un proveedor que el host ya registró; nunca nombra un módulo que importar.
- El host es dueño de las credenciales, la elección de modelo, el espacio de trabajo, los presupuestos y la cancelación. No hay una abstracción oculta de proveedores: cada adaptador traduce el protocolo de su proveedor.

## Consecuencias

- Añadir un executor de CLI es añadir un registro de rasgos.
- Los controles de modelo tipados requieren una versión de executor declarada y un ejecutable directo; un shim `.cmd`/`.bat` de Windows se rechaza.
- `claude-code` se ejecuta con `--dangerously-skip-permissions` porque en una ejecución sin interfaz no hay aprobador interactivo (consulte ADR-007).
- Ambos proveedores de API llaman al mecanismo de reintentos con `maxAttempts: 1`, de modo que por defecto no se reintenta nada.

## Evidencia

- `packages/adapter-cli/src/catalogue.ts` y `packages/adapter-cli/src/executors/*.ts`.
- `packages/adapter-api/src/registry.ts` y `packages/adapter-api/src/transport.ts`.
- `packages/adapter-openai/src/openai-provider.ts` y `packages/adapter-anthropic/src/anthropic-provider.ts` (`maxAttempts: 1`).
