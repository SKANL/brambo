# ADR-005: Versionar por rechazo, nunca migrar

## Estado

Aceptada. Vigente en 0.5.x.

## Contexto

Los almacenes anteriores a 1.0 (registro, memoria, flujos) los escribe una versión y los lee otra. Un almacén leído a medias es peor que uno sin abrir, y una ruta de migración es un compromiso a largo plazo que ningún consumidor actual necesita.

## Decisión

Cada formato persistido y cada contrato llevan una versión. Un almacén sellado con otra versión se rechaza con un error con código que nombra la discrepancia; nunca se lee parcialmente ni se migra. Un almacén ausente no es un fallo: se sella y se usa.

## Consecuencias

- Actualizar a través de un cambio de formato exige instalar una versión al menos tan nueva como la que escribió los datos.
- El registro distingue un almacén más nuevo (`BRAMBO_REGISTRY_STORE_VERSION_MISMATCH`) de uno irreconocible (`BRAMBO_REGISTRY_STORE_UNAVAILABLE`).
- La regla es una cláusula publicada de la suite de contrato de memoria, por lo que los proveedores de memoria de terceros deben cumplirla.

## Evidencia

- `packages/contracts/src/errors.ts` (comentario de `contractMemoryStoreVersionMismatch`: versionar por rechazo, nunca migrar).
- `packages/registry/src/store.ts` (`STORE_VERSION`).
- Los sellos de formato de `packages/memory-filesystem` y `packages/memory-sqlite`; `packages/contracts/src/contract-suite/memory-clauses.ts`.
- `packages/workflow-store-sqlite/src/schema.ts` (`BRAMBO_WORKFLOW_SCHEMA_UNSUPPORTED`).
