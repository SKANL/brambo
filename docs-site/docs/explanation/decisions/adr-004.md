# ADR-004: Fail-closed, hand-written validation behind Standard Schema

## Status

Accepted. In force for 0.5.x.

## Context

`@brambodev/contracts` must stay dependency-free so a port author can install it alone, yet hosts already use schema libraries such as Zod or Valibot. Validation sits on trust boundaries where a permissive default is a vulnerability.

## Decision

- brambo's own schemas are hand-written validators, exposed through a structural reproduction of the Standard Schema v1 interface (`~standard`), so libraries that implement Standard Schema interoperate without a dependency.
- Validation fails closed: anything unknown, unproven or malformed is refused with a coded `BramboError`, never defaulted.

## Consequences

- No package depends on a schema library.
- Validators report coordinates inside the message rather than in `path`.
- Callers route on `error.code`, never on message text.
- Port authors may write a provider configuration schema with any Standard Schema library, provided it validates synchronously where the contract requires it.

## Evidence

- `packages/contracts/src/standard-schema.ts` and `packages/contracts/src/validation.ts`.
- No `zod` or `valibot` entry in any `packages/*/package.json`.
- Fail-closed examples: `kernel/src/intercept.ts` (cap validation), `projection/src/engine.ts` (mode), `contracts/src/sandbox.ts` (`validateSandboxCapabilities`).
