# ADR-005: Version by reject, never migrate

## Status

Accepted. In force for 0.5.x.

## Context

Pre-1.0 stores (registry, memory, workflow) are written by one build and read by another. A partially read store is worse than an unopened one, and a migration path is a long-term commitment no current consumer needs.

## Decision

Every persisted format and contract carries a version. A store stamped with another version is refused with a coded error that names the mismatch; it is never partially read or migrated. An absent store is not a failure: it is stamped and served.

## Consequences

- Upgrading across a format change requires installing a build at least as new as the one that wrote the data.
- The registry distinguishes a newer store (`BRAMBO_REGISTRY_STORE_VERSION_MISMATCH`) from an unrecognizable one (`BRAMBO_REGISTRY_STORE_UNAVAILABLE`).
- The rule is a published clause of the memory contract suite, so third-party memory providers must follow it.

## Evidence

- `packages/contracts/src/errors.ts` (comment on `contractMemoryStoreVersionMismatch`: version by reject, never migrate).
- `packages/registry/src/store.ts` (`STORE_VERSION`).
- `packages/memory-filesystem` and `packages/memory-sqlite` format stamps; `packages/contracts/src/contract-suite/memory-clauses.ts`.
- `packages/workflow-store-sqlite/src/schema.ts` (`BRAMBO_WORKFLOW_SCHEMA_UNSUPPORTED`).
