# ADR-009: Projection under an ownership ledger

## Status

Accepted. In force for 0.5.x.

## Context

brambo writes into files that vendor tools and people also edit. It must reverse safely and must not invent a parallel configuration format that vendors do not read.

## Decision

- Projection writes each executor's own vocabulary at the location that executor reads.
- A ledger (`~/.brambo/projection-ledger.json`) records what brambo owns. The native file lands before the ledger records it, so a crash under-claims.
- Targets run sequentially with per-target failure containment; failures are typed results.
- An unreadable ledger turns writes into inspections. Remediation (`adopt`, `release`, `repair`, `discard`) has an `inspect` mode, so the preview and the act are the same call.

## Consequences

- Drift (`edited`, `removed-by-user`, `foreign-collision`) is reported, never resolved by writing.
- Projection is single-writer per file; concurrent projection of one file is unsupported, and a file changed between read and write fails that target.
- Project-scope skills are not projected where no verified vendor location exists.

## Evidence

- `packages/projection/src/engine.ts` and `packages/projection/src/ledger.ts`.
- `packages/projection/README.md`.
- `packages/environment/src/index.ts` (`remediate`, finding kinds).
