# ADR-008: Single-authority SQLite run store with CAS, leases and fencing

## Status

Accepted. In force for 0.5.x.

## Context

Durable workflows need atomic revisions and safe takeover after a crash, but brambo must not claim distributed authority it cannot prove. The store is a port (`RunStore`), so the reference implementation sets the bar others must meet.

## Decision

- The reference store is `workflow-store-sqlite` on `node:sqlite`, loaded lazily so importing the package has no side effects.
- Commits are compare-and-swap on a revision; state, events and receipt updates land in one transaction.
- Leases are all-or-nothing claims with monotonic fencing epochs; a commit must present current epochs, owner, token hash and expiry. Raw tokens are never stored.
- Writes use `BEGIN IMMEDIATE`; contention beyond a bounded wait raises `BRAMBO_WORKFLOW_STORE_BUSY` instead of overwriting.
- Scope is one authoritative host; the same published contract suite runs against SQLite and a local-process backend.

## Consequences

- The SQLite store requires Node.js >=24.15.0 while every other package supports Node.js >=20.
- Shared mounts, clustering and failover are not claimed; other topologies implement `RunStore` and pass `runWorkflowStoreContractSuite`.
- Imports between stores are fenced copies, not distributed transactions.

## Evidence

- `packages/workflow-store-sqlite/src/store.ts`, `coordination.ts`, `sqlite.ts` and `schema.ts`.
- `packages/workflow-store-sqlite/package.json` (`engines.node: >=24.15.0`).
- `packages/contracts/src/contract-suite/workflow-clauses.ts` (`runWorkflowStoreContractSuite`).
