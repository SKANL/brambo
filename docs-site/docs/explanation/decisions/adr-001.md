# ADR-001: Zero-dependency microkernel

## Status

Accepted. In force for 0.5.x. Referred to as AD-1 in source comments.

## Context

brambo composes executors, workspaces, registries and stores that change at different speeds and come from different vendors. If the substrate that mounts them carried policy or vendor knowledge, every consumer would inherit it, and a change to one vendor would ripple through the core.

## Decision

`@brambodev/kernel` has zero runtime dependencies and never imports `@brambodev/contracts`. It provides only plugin manifests, a service graph, ordered lifecycle, a scoped event bus, layered configuration, an action pipeline with budgets, and a record stream. It knows nothing about executors, registries or projection.

## Consequences

- Types both packages need (Standard Schema shapes, the semver pattern) are duplicated on purpose, and a parity test keeps the kernel and contracts error codes aligned.
- The kernel applies a plugin's `configSchema` itself instead of trusting the plugin.
- Transports, provider registries, durable stores and permission UI stay out of the kernel permanently.
- Kernel errors are a separate hierarchy (`BramboKernelError`), so hosts branch on `error.code`.

## Evidence

- `packages/kernel/package.json` declares no `dependencies`.
- `packages/kernel/test/guard.test.ts` fails on any runtime dependency, a second entry point, or an import of `@brambodev/contracts`.
- `eslint.config.js` bans `@brambodev/contracts` inside `packages/kernel/**` with the message "the kernel never imports @brambodev/contracts (AD-1)".
- `packages/contracts/test/kernel-code-parity.test.ts` keeps the duplicated error codes in agreement.
