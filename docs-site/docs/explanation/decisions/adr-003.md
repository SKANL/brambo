# ADR-003: Three worlds over a shared core

## Status

Accepted. In force for 0.5.x.

## Context

Consumers want different things: run one executor turn inside a product, run long resumable workflows, or keep vendor configuration in sync. Forcing all three on everyone would make the smallest use case pay for the largest.

## Decision

Packages are grouped into a shared core (`contracts`, `kernel`) and three worlds: session (`session` and its adapters, workspaces and sandboxes), durable (`orchestration`, `runtime-local`, `workflow-*`, `workspace-artifacts-local`) and environment (`registry`, `projection`, `environment`). Each world has its own entry package. The CLI is a convenience binding over the session and environment worlds.

## Consequences

- A host installs only the world it needs; `@brambodev/session` re-exports what its surface uses.
- World membership is a documentation and packaging convention. The tier map, not the world grouping, is what the build enforces, so a world boundary could in principle be crossed by a lower-tier import.
- The CLI is documented as an appendix, not as the architecture.

## Evidence

- `README.md` package map grouped by world.
- `docs-site/sidebars.ts` package reference grouped by world.
- `packages/contracts/test/topology.test.ts` (the enforced rule is tiers, not worlds).
