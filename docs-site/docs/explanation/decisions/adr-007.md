# ADR-007: brambo is not a sandbox; authority is host-owned

## Status

Accepted. In force for 0.5.x.

## Context

Tool execution, methods and executors cross trust boundaries. A type or adapter seam existing must not read as a guarantee, and brambo runs on hosts whose isolation it cannot observe.

## Decision

- brambo validates and records; the host authorizes. Authentication, credentials, approval, deployment, retention and TLS are host responsibilities.
- `ToolProvider` is discovery only. Execution requires `executeTool`, a `ToolExecutor` and a caller-owned sandbox session, with exact argv and no shell or JavaScript handlers.
- Sandbox providers report capability evidence; a policy that requires unproven controls is refused before a session exists. OS isolation is claimed only where a provider demonstrated it.

## Consequences

- The CLI adapter is documented as running vendor processes with the user's privileges.
- Linux bubblewrap is advertised only after a functional probe; macOS claims filesystem evidence only; Windows requires an external broker; the remote provider is an injected transport.
- The workflow coordinator ships no TLS and no authentication of its own; it calls host callbacks.
