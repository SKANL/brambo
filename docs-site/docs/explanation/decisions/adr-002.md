# ADR-002: Ports in contracts and an enforced downward topology

## Status

Accepted. In force for 0.5.x. Referred to as AD-2 in source comments.

## Context

With 28 packages, a dependency diagram in a document cannot fail a build. Earlier guards were bypassed in practice: once by a relative import that climbed into another package, once by a re-export that smuggled composition into the CLI.

## Decision

- Every port, validator, coded error and contract suite lives in `@brambodev/contracts`.
- Every package has a numbered tier (0 to 8) and may import only strictly lower tiers. The tier table is executable and checked in both directions: a package without a tier fails, and a tier for a deleted package fails.
- Relative imports out of a package are banned everywhere.
- `@brambodev/cli` is a thin binding: it may not import `node:fs` or any composition name from any `@brambodev/*` package.

## Consequences

- Adding a package means choosing its tier in the same change.
- Same-tier packages cannot import each other, which is why `lock` got its own tier when two tier-2 packages needed it.
- A port author can depend on `@brambodev/contracts` alone and run the published suites.
- The CLI cannot own composition, even through a re-export.

## Evidence

- `packages/contracts/test/topology.test.ts` (the `TIER` map and the strictly-downward rule).
- `eslint.config.js` (`no-restricted-imports` for `../..`, the CLI `node:fs` ban and the composition-name ban, with comments recording the bypasses that motivated them).
- `packages/contracts/README.md` (contracts-only install).
